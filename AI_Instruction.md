# Дружба Свет — инструкции для AI

Блог и CMS «Дружба Свет»: статьи с ревью по блокам, подборки для гостей, кабинет клиента,
личный «План», «Цели», уведомления. Боевой сайт: https://blog.ds.info (CentOS 9, сборка на сервере).
Разработчик и владелец — Алексей (smilesoul009). Общение — по-русски.

## Стек
Nuxt 4 (`app/`, Nitro `server/`), Nuxt UI 4, Tailwind CSS v4, TipTap, Prisma 7 + PostgreSQL, pnpm, zod.
Пути: `#server/...` — сервер, `~~/shared/...` — общий код клиента и сервера.

## Как работаем
- Код в GitHub, Claude работает в ветках `feat/…`, `fix/…`, `style/…`, `docs/…`, `chore/…` и открывает pull request.
  Сливает **только Алексей** (Create a merge commit), после проверки по чек-листу из описания PR.
- **Перед каждой правкой проверить, что PR ещё открыт.** Если слит — новый PR от свежего `main`.
- Один PR — одна тема. Доработки по открытому PR — в ту же ветку.
- В сессиях Claude реестр npm бывает закрыт: сборку и проверку типов не запустить. Тогда особенно внимательно
  сверять типы и места использования, а чек-лист в PR — подробный.
- Миграции Prisma, если нельзя запустить `prisma migrate dev`, пишутся вручную в формате Prisma
  (`prisma/migrations/<YYYYMMDDHHMMSS>_<имя>/migration.sql`), только добавляющие изменения.
- Обсуждение — без кода, пока Алексей не скажет «можно писать код». Для интерфейса — сначала эскиз.

## Версии, коммиты, CHANGELOG
- SemVer, версия в `package.json`. PATCH — исправления, MINOR — новое совместимое, MAJOR — ломающее.
- Коммиты — Conventional Commits на русском: `тип(область): описание`, затем 2–5 пунктов.
- Версия поднимается отдельным PR `chore: версия X.Y.Z` (package.json + раздел в `CHANGELOG.MD`), тег ставит Алексей.
- В ответе после каждого завершённого куска — блок «Версионирование»: версия, коммит, миграции, строки CHANGELOG, тег.

## Интерфейс — только из стандартных блоков
Интерфейс собирается из общих компонентов и утилит, чтобы дизайн менялся в одном месте.
Справочник: **`docs/ui-components.md`** — смотреть его, а не искать по проекту. Новый общий блок —
сначала в справочник и в `app/components`, потом использовать.
Основное: кнопки 36 px, `rounded-xs`, ширина кнопок формы 130 px, серая палитра; одна форма на создание и правку
(«Закрыть», пока нет изменений; «Сохранить / Отмена» при изменениях); удаление — с «Отменить» на 5 секунд.
Админка — только для компьютера.

## Безопасность
- Каждый эндпоинт начинается с проверки: `authCheck`, `permissionCheck(...)`, для плана и целей — `planCheck`.
- Данные пользователя — только свои (`userId` в условии запроса).
- `passwordHash` никогда не выбирать и не логировать; запросы к User — с явным `select`.
- Режим «просмотр как пользователь» — только чтение (`event.context.readOnly`); личный план недоступен.
- Секреты — только в `.env` (в git не попадает), дампы базы — не в репозиторий.

## Документы
- `docs/ui-components.md` — справочник стандартных блоков интерфейса.
- `CHANGELOG.MD` — история версий.
- `Инструкции/` — инструкции для пользователей (.docx).
- `deploy/oldsite/README.md` — архивные версии сайта на oldsite.druzhba-svet.ru (Docker): сразу после выкладки
  релиза (`deploy.sh`) на сервере `oldsite snapshot`. На сервере git нет — файлы выкладываются из WebStorm. Колонки в базе не удаляем — старые версии и возврат функций опираются на них.
